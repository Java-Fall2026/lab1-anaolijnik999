# Робота з AI — Лабораторна робота №4

Для виконання лабораторної роботи №4 я використовувала AI-асистента Gemini із ключовим промптом: «Напиши для Java 21 реалізацію GenericRepository<T> з IdentityExtractor<T>, DuplicateIdentityException, тестами JUnit 5, оновленням Main та SearchBenchmark для порівняння Map і List на 100 000 елементів за варіантом логістики». Спочатку AI запропонував у тесті перевіряти порожній ідентифікатор через створення `new Vehicle("   ", ...)`, але цей тест падав ще в конструкторі класу `Vehicle` через валідацію з попередніх лабораторних робіт. Я помітила це під час запуску `./gradlew.bat test` за стектрейсом помилки в рядку створення об'єкта. Також я перевірила, щоб сутності з ЛР1–ЛР3 не змінювалися, для змінюваного класу `Shipment` як ідентифікатор використовувалося незмінне поле `trackingNumber`, а логування дублікатів не дублювалося двічі. Самостійно я виправила тест на використання репозиторію зі спеціальним `IdentityExtractor`, який повертає порожній рядок для валідного об'єкта `Vehicle`, а також додала дублікат запису в `data/vehicles.csv`. Це дозволило повністю виконати вимоги завдання без зміни існуючих доменних класів.
